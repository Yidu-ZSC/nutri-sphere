# 下一步：数据密度、开放数据接入、用户路径验证

针对当前 Phase 1 应用（70 节点 / 126 边，主题大厅 + 2D 层次通路），三个优先方向的具体建议。

## 1. 数据密度与可读性

**问题**：图已经不小，普通用户进入主题后仍可能看到过多节点。

**建议动作**：
- 主题大厅选中后，默认开启「隐藏非匹配节点」（`hide=1`），并在 URL 中保留。
- 利用已有 `audience` 与 `mechanism_depth`：
  - 普通层默认只显示 `audience=general` 的边，以及 `mechanism_depth` 为 `summary` 或缺省的节点。
  - 专家层展开 `deep_reader` 与 `technical`。
- 主题卡片的 blurb 保持 ≤40 字，并在卡片上标注「教育整理，非建议」。
- 考虑增加「简化视图」开关：只保留当前主题相关的 1-跳邻域。

**验收**：非专业用户打开任意主题后，首屏可读节点 ≤ 15 个，且能看到方向与局限性。

## 2. 开放数据接入节奏

**原则**：小步、边级证据元数据必填、局限性明确。不做黑盒相关性投影。

**建议第一批（低风险）**：
- Nutri-Score / NOVA 公开映射：为已有食物节点补充 `processing_level` 或 `nutri_score_band` 属性（不改变现有边的证据类型）。
- 仅作为节点元数据，不自动生成新的「风险边」，除非有明确的文献或书摘支持。
- GBD 饮食相关汇总：以「国家/人群级生态相关」形式加入局限性说明，不作为个体因果。

**流程**：
1. 在 `docs/` 写明数据源、许可证、映射规则。
2. 新增边必须带 `evidence_type`、`limitations`、`citation`（若适用）。
3. 通过 PR + `validate:data` 后合入。
4. 不一次性导入大量原始表格。

**暂不做**：个体风险评分、补充剂建议、诊疗性结论。

## 3. 用户路径验证

**目标**：确认非专业用户能从主题大厅进入、理解方向与局限性、离开时不会误以为医疗建议。

**建议做法**：
- 招募 2–3 名非营养/医学背景用户（可含知识库使用者）。
- 任务：
  1. 打开站点，不给任何提示。
  2. 自己选一个感兴趣的主题。
  3. 点 1–2 条边，说出自己看到了什么。
  4. 回答：这是建议我改变饮食吗？证据强度如何？有什么限制？
- 记录：卡点（能否找到主题、能否读懂方向、是否注意到免责声明）、卡点（节点太多、文案难懂、不知道该点哪里）。
- 产出：一页观察记录（可放 `docs/user-observations.md`），不改代码也可先记。

**成功标准**：用户能说出「这是关联方向与证据说明，不是个人处方」。

## 优先级建议

1. 先做用户路径验证（低成本，直接影响产品感受）。
2. 同步小幅改进密度控制（默认隐藏非匹配 + 普通层过滤）。
3. 再开始第一批开放数据映射（文档 + 少量节点属性）。

以上均保持「教育与研究工具、非诊疗」边界。
