# 数据存储决策：保持版本化 JSON，暂不上 Cloudflare 数据库

## 决定

**当前不使用 Cloudflare D1 或其他后台数据库替代现有 JSON 数据文件。**

继续使用版本化、经 CI 校验的静态 JSON，由 Cloudflare CDN 全球分发。

## 理由

| 维度 | 现状 | 数据库的收益 |
|------|------|--------------|
| 数据量 | 约 70 节点 / 126 关联 | 几乎无 |
| 更新方式 | 人工策展 + PR + CI 校验 | 低（仍需审核流程） |
| 查询模式 | 前端一次加载全图，再做过滤 | 数据库优势不大 |
| 全球访问 | Cloudflare 已缓存静态文件 | 已足够快 |
| 维护成本 | 低（文件 + Git） | 引入 D1/Workers 后更高 |

架构文档已明确：先用版本化 JSON，等查询复杂度真正上来再考虑图数据库。

## 什么时候再评估

满足以下任一条件时再考虑：
- 节点/边数量达到数千级，且需要复杂实时查询。
- 需要用户贡献、审核、版本回滚等动态写入。
- 需要按用户、主题做细粒度权限或个性化存储。

## 后续可选路径（不现在做）

1. 数据继续增长但仍只读：可在 Cloudflare Workers 上加一层只读 API（仍从 JSON 或 R2 读取）。
2. 出现真正动态写入或复杂查询需求：再引入 Cloudflare D1。

## 约束

- 不改变现有数据文件结构与 CI 校验流程。
- 不引入数据库相关代码或配置。
- 教育边界与证据可追溯不变。

以上供架构对齐使用。
