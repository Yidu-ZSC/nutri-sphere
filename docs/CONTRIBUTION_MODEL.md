# ClearDiet 外部协作机制

## 1. 网站协作 vs GitHub 公开协作

| 维度 | cleardiet.org 网站协作 | GitHub 公开仓库 |
|------|------------------------|-----------------|
| 入口 | 用户已在使用产品，门槛低 | 需懂 Git / PR，门槛高 |
| 贡献类型 | 适合「补充一段摘录」「标记一处问题」 | 适合代码、文档、结构化数据 |
| 审核 | 需自建审核后台 | PR + Review 现成 |
| 激励可见性 | 可在网站展示贡献者 | 仅在仓库可见 |
| 数据安全 | 可控，先存待审再入库 | 公开后即暴露 |
| 维护成本 | 需开发协作功能 | 几乎零额外开发 |

**建议**：  
- **内容贡献**（摘录、校对）优先走网站，普通用户可参与。  
- **代码与结构**走 GitHub，开发者参与。  
- 两者可并存，网站提交的内容经审核后同步到仓库。

## 2. 如何吸引外部贡献者

- **明确价值**：说明「你补的一段摘录，会帮助更多人看懂这条关联」。
- **降低门槛**：网站提供「补充摘录」入口，不要求会 Git。
- **可见反馈**：贡献被采纳后，在来源页或边抽屉标注「由 XX 补充」。
- **从小处开始**：先开放「校对现有摘录是否准确」，再开放「新增摘录」。

## 3. 贡献指南与审核流程

### 贡献指南要点
- 摘录必须来自公开书籍或文献原文，不改写结论。
- 注明书名、章节或页码（如有）。
- 保留局限性，不写疗效或建议。
- 不提交诊断、治疗或补充剂用法。

### 审核流程
1. 用户提交 → 进入待审队列。
2. 管理员查看原文对照、来源是否可追溯。
3. 通过后写入图谱，并标注贡献者；不通过则说明原因。
4. 定期将已入库内容同步到仓库。

## 4. 激励机制

| 方式 | 说明 | 成本 |
|------|------|------|
| **署名** | 在边或来源页显示贡献者名 | 低 |
| **贡献榜** | 后台或关于页展示本月贡献者 | 低 |
| **徽章** | 累计贡献数对应等级（可选） | 中 |
| **优先体验** | 贡献者可提前看到新主题（如环境） | 中 |

初期建议只做**署名 + 贡献榜**，足够建立认可感，且不增加复杂逻辑。

## 5. 分阶段建议

**阶段 1**：保持 GitHub 公开，先在网站增加「报告问题 / 建议补充」入口，人工处理。  
**阶段 2**：上线待审队列与审核后台，开放「补充摘录」。  
**阶段 3**：增加署名与贡献榜，评估是否进一步开放新增边。

以上供协作机制对齐使用。
