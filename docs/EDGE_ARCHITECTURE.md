# ClearDiet 边的信息架构

## 1. 目的

边是 ClearDiet 的核心价值。随着时间推移，每条边的信息量会增加，边的数量也会增加。需要设计可扩展的结构，让用户通过边理解「公开资料里怎么描述这条关联」。

## 2. 当前问题

- 摘录过短（≤300 字），用户难以完整理解这条边在讲什么。
- 同一本书多处相关内容、多本书/多文献对同一关联的描述，没有结构表达。
- 来源显示为文件名（如 `植物性饮食与慢病_救命饮食中国健康调查报告.md`），不是图书原名。
- 引用过的图书或文献没有独立简介页，无法延伸阅读。

## 3. 字段调整

### 3.1 原文摘录
- 字段名由 `excerpt` 改为展示名「原文摘录」。
- 长度限制放宽至 800–1200 字，以能让用户理解这条边在讲什么为准。
- 保留原文语气，不改写成结论。

### 3.2 来源
- 新增 `source_title`：图书或文献的原名（如「救命饮食：中国健康调查报告」）。
- `source_file` 保留为内部文件名，仅供系统追溯，不直接展示给用户。
- 界面显示 `source_title`，点击可进入该来源的简介页。

### 3.3 多处 / 多来源
一条边可以有多条证据。建议结构：

```json
"evidences": [
  {
    "source_title": "救命饮食：中国健康调查报告",
    "source_file": "植物性饮食与慢病_救命饮食中国健康调查报告.md",
    "excerpt": "……原文摘录……",
    "note_id": "optional",
    "limitations": "书中综述"
  },
  {
    "source_title": "另一本书或文献标题",
    "source_file": "...",
    "excerpt": "……",
    "limitations": "……"
  }
]
```

- 同一本书的多处相关内容：在同一 `source_title` 下可有多条 excerpt，或合并为一条较长摘录并注明位置。
- 多本书/多文献：`evidences` 数组中多条记录。
- 界面默认展示第一条，其余用「还有 N 处相关描述」展开。

### 3.4 来源简介页
系统中引用过的每本图书或文献，应有独立简介页：
- 原名、作者、出版年
- 一两句简介
- 本书中被引用的边列表（可点击跳回图谱）
- 外部链接（如有）

数据上可单独维护 `sources` 表：

```json
{
  "id": "china_study",
  "title": "救命饮食：中国健康调查报告",
  "authors": "T. Colin Campbell",
  "year": 2006,
  "description": "基于中国农村调查的饮食与慢性病关联讨论。",
  "file": "植物性饮食与慢病_救命饮食中国健康调查报告.md"
}
```

边的 `evidences[].source_title` 对应到此表。

## 4. 界面呈现

点开边后，抽屉顺序：

1. **标题**：关系描述
2. **起止**：A → B
3. **原文摘录**：第一条，足够长度
4. **来源**：原名（可点击进入简介页）
5. **局限性**
6. **还有 N 处相关描述**（折叠，展开后显示其他 evidences）
7. **方向 / 强度徽章**
8. **更多说明**（证据类型、DOI 等）

## 5. 迁移

- 现有边：`excerpt` 保留，补充 `source_title`（从文件名映射或人工填写）。
- 长度：逐步把关键边的摘录扩充到足够理解的长度。
- 多来源：先支持数组结构，现有单条边作为 `evidences` 的第一条。
- 简介页：先做静态页面，列出已引用的书，后续再完善。

## 6. 边界

- 摘录保留原文，不改写成疗效或建议。
- 局限性必须保留，不因摘录变长而省略。
- 免责声明始终可见。

## 7. 版本

- v0.1：提出边的信息架构，包括原文摘录、来源原名、多证据结构、来源简介页。

以上供边的扩展对齐使用。
