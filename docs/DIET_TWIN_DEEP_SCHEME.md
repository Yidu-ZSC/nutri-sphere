# 饮食孪生深化方案

当前为问卷 + 指标条 MVP。本方案在其基础上增加饮食记录、状态反馈与解读，数据存本地。

## 1. 目标

让用户能：
- 记录自己的饮食（不上传服务器）
- 看到基于记录的教育向状态反馈
- 阅读简短解读（链回图谱与健康饮食方式）
- 假设改变并对比

持久标注：**「教育模拟，非诊断」**。

## 2. 功能结构

### 2.1 饮食记录
- 用户可添加单条记录：日期、餐次（早/午/晚/加餐）、简短描述。
- 支持粘贴多行日志（每行一条）。
- 列表展示最近 7 天 / 30 天，可删除单条。
- 不要求食物数据库或卡路里。

### 2.2 状态反馈
基于最近记录自动推断（教育向）：
- 植物性比例倾向
- 超加工频率倾向
- 纤维相关词汇出现次数
- 炎症关联方向（组合以上）

用指标条 + 简短文字展示，不给出数字分数。

### 2.3 解读
每个指标下方一句解读：
- 「公开资料中常把这种选择与…联系起来」
- 链接「查看图谱里的相关讨论」
- 可选「查看相关饮食模式」

### 2.4 假设对比
保留现有问卷调整能力，但标注「假设」与「基于记录」的区别。
用户可切换查看：
- 基于记录的当前状态
- 假设改变后的状态

## 3. 本地数据模型

使用 localStorage，键名 `cleardiet.dietTwin.v1`。

```ts
type DietRecord = {
  id: string;           // uuid
  date: string;         // YYYY-MM-DD
  meal: 'breakfast' | 'lunch' | 'dinner' | 'snack';
  text: string;         // 用户原文，不改写
  createdAt: string;    // ISO
};

type TwinSnapshot = {
  plantRatio: 'low' | 'mid' | 'high';
  upfFreq: 'low' | 'mid' | 'high';
  fiberFeel: 'low' | 'mid' | 'high';
  inflammationDir: 'low' | 'mid' | 'high';
  basedOn: 'records' | 'hypothesis';
  updatedAt: string;
};

type DietTwinStore = {
  version: 1;
  records: DietRecord[];
  hypothesis: {
    plantRatio: 'low' | 'mid' | 'high';
    upfFreq: 'low' | 'mid' | 'high';
    fiberFeel: 'low' | 'mid' | 'high';
  } | null;
  lastSnapshot: TwinSnapshot | null;
};
```

### 推断规则（教育向，前端常量）
- 植物性词汇：蔬菜、豆、全谷、水果、素… → 计数
- 超加工词汇：风味零食、罐装、即食、加工肉… → 计数
- 纤维词汇：纤维、豆、全谷、蔬菜… → 计数
- 按最近 7 天记录比例映射到 low/mid/high
- 无记录时回退到问卷假设

## 4. 界面结构

1. **顶部**：标题 + 永久「教育模拟，非诊断」
2. **记录区**：添加记录 / 粘贴日志 + 最近列表
3. **当前状态**：基于记录的指标条 + 解读
4. **假设对比**：可切换查看假设改变后的条
5. **链回**：每个指标下方「查看图谱里的相关讨论」

## 5. 文案规则

- 用「公开资料中常被描述为…」
- 不使用「你的风险」「建议你吃」「治疗」「预防」「逆转」
- 解读固定带「教育模拟，非个人检测」

## 6. 实现要点

- 新增 `src/lib/dietTwinStore.ts`：读写 localStorage、推断逻辑。
- 现有问卷保留作为「假设」入口。
- 新增记录列表与添加表单。
- 状态条根据 `lastSnapshot.basedOn` 切换文案。
- 不引入后台。

## 7. 验收

- 可添加、查看、删除本地记录。
- 基于记录生成状态条与解读。
- 可切换假设对比。
- 刷新后数据仍在。
- 无数据上传服务器。
- 持久可见「教育模拟，非诊断」。

## 8. 优先级

1. 本地数据模型 + 记录列表
2. 基于记录的状态推断与解读
3. 假设对比与链回完善

以上供开发对齐使用。
